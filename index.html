FAQ

A few more answers.

Is QuotaGrain for Codex an official Codex product?+

No. QuotaGrain for Codex is an independently developed third-party tool and is not affiliated with or partnered with OpenAI.

Who is QuotaGrain for Codex for?+

QuotaGrain for Codex is for Mac users who work with multiple Codex accounts or use external APIs and local models in separate Codex clients. It brings quota, reset times, and local token usage into one panel.

Can I run multiple Codex clients and use external APIs?+

Yes. In addition to checking quotas, QuotaGrain for Codex can open a separate Codex client for each account, so you can use multiple accounts at once. You can also configure external API services, API keys, and models for use in the corresponding Codex client. External services must support the OpenAI Responses API.

Where are isolated account files stored?+

Independent accounts created through our software are stored in ~/.codex/accounts/ on your Mac. Each account has its own configuration, authentication information, and session data. Client data is stored in desktop/ within that account’s directory. Existing default account data in ~/.codex remains unchanged.

Can Codex updates affect QuotaGrain for Codex?+

Yes. QuotaGrain for Codex depends on current Codex and macOS behavior. Upstream changes or restrictions may make some features unavailable.

What does support unlock?+

Manage up to two accounts for free, or support the developer to unlock unlimited accounts. Both Codex and external API accounts count toward the limit. Automatic refresh, quota alerts, and privacy protections are the same. Unlocking expands account capacity; it does not increase quota from OpenAI or your API provider.

Does API token usage show my remaining balance?+

No. Token totals for external APIs and local models come from local usage records. They do not represent provider balances, remaining quota, or billed amounts.

What do I need to use QuotaGrain for Codex?+

You need an Apple Silicon Mac running macOS 13 or later, with Codex installed for sign-in and client launching. External APIs and local model services must support OpenAI Responses.
